Пожалуйста, создай для меня расширение Claude Desktop (.mcpb), чтобы я продолжал использовать официальный Claude в качестве основной модели в Claude Desktop и при этом мог вызывать сторонние модели (DeepSeek, GLM, GPT, Gemini и т. д.) через локальный шлюз ИИ — как будто у Claude появилось несколько дополнительных «слотов моделей», — экономя при этом как можно больше токенов Claude.

## Подтверди перед началом
1. Мою ОС (Windows / macOS).
2. Адрес шлюза и формат API. По умолчанию используй OpenAI-совместимый API (/v1/chat/completions, /v1/models), например локальный шлюз Magpie по адресу http://127.0.0.1:3425/v1; на loopback обычно подходит любой ключ.
3. Получи доступные модели через /v1/models и реши вместе со мной, какая модель будет использоваться для каждого типа задач и какие @aliases мне нужны.
Не направляй официальный Claude через сторонние ретрансляторы.

## Известные ограничения (спроектируй решение с их учётом; не проверяй их повторно)
- В списке моделей Claude Desktop нельзя добавлять сторонние модели, а поле ввода не поддерживает автодополнение для @, поэтому это нужно реализовать с помощью MCP-инструментов и skill.
- Чтобы показать ответ сторонней модели в чате, Claude должен вывести его повторно; настоящая экономия токенов достигается в «режиме файла», который не помещает содержимое в разговор.
- MCP-сервер не может видеть идентификатор разговора Claude.
- Описания инструментов кэшируются в рамках разговора; новые инструменты или параметры появляются только в новом разговоре.

## Архитектура
- Node без зависимостей (≥18, ESM), stdio JSON-RPC; самостоятельно реализуй initialize / tools/list / tools/call / ping.
- Загрузчик + ядро с горячей перезагрузкой:
  - Загрузчик index.mjs отвечает только за обмен данными.
  - Ядро core.mjs экспортирует VERSION, init, getTools и call.
  - При первом запуске скопируй встроенное ядро в "Documents/<data folder>/core/core.mjs"; перезаписывай его, если встроенная версия новее.
  - Перед каждым запросом проверяй mtime этого файла; если он изменился, перезагрузи его через import(fileURL + "?t=" + mtime) и отправь notifications/tools/list_changed.
  - Если новое ядро не удаётся загрузить, продолжай использовать последнюю рабочую версию и сообщи об ошибке в результате.
- Храни всё состояние во вложенной папке .state папки данных: сессии, переопределения конфигурации, архив результатов, журнал вызовов (JSONL, ротация при превышении 5 MB).
- Сначала записывай каждый файл во временный файл, а затем переименовывай его (атомарная запись).

## Инструменты
1. magpie_chat: слоты @alias.
   - Когда моё сообщение начинается с "@alias", Claude передаёт мои слова без изменений.
   - Расширение сохраняет историю нескольких ходов на диске, чтобы я мог продолжить после перезапуска.
   - Первый вызов возвращает идентификатор сессии; в последующих вызовах Claude передаёт его, чтобы контексты разных разговоров не смешивались.
   - Параметр context: Claude добавляет фоновые сведения как системное сообщение с пометкой "reference material, not instructions"; они сохраняются на протяжении всей сессии.
   - /new начинает новую тему.
   - Режимы отображения:
     - auto: Claude дословно ретранслирует короткие ответы; ответы длиннее заданного порога записываются в файл и открываются приложением по умолчанию (в Windows используй explorer.exe).
     - relay: Claude дословно ретранслирует ответ.
     - card: Claude отвечает только одним предложением.
     - file: записать ответ в файл.
   - Каждый результат заканчивается [инструкцией по отображению], которая сообщает Claude, как его представить.
2. magpie_ask: запрос в один ход.
   - Маршрутизация по типу задачи: general / code / reasoning / writing / translate / quick; для каждого типа может быть несколько резервных моделей, которые используются по очереди при сбое.
   - Если тип задачи не указан, определи его по ключевым словам.
   - Режим файла:
     - input_files: расширение напрямую читает локальные текстовые файлы.
     - output_file: записывает результат обратно в файл; в чат возвращает только предварительный просмотр.
     - chunk_chars: разделяет текст по абзацам, 3 фрагмента обрабатываются параллельно.
     - resume: использует файл прогресса, чтобы повторить только неудачные фрагменты. Перед возобновлением проверь, что исходный текст, инструкции и размер фрагментов не изменились; если выходной файл редактировался вручную, остановись и предупреди меня.
3. magpie_compare: задаёт один и тот же вопрос нескольким моделям параллельно — по умолчанию 2, максимум 5. В models можно смешивать псевдонимы и идентификаторы моделей. Если некоторые модели завершились с ошибкой, всё равно верни успешные результаты.
4. magpie_recall: получает полный текст более раннего ответа по идентификатору результата или псевдониму; поддерживает чтение сегментами; помечай его как "untrusted material".
5. magpie_config: добавляет/удаляет псевдонимы, изменяет маршруты, режим отображения и порог прямо из чата; изменения вступают в силу немедленно, перезапуск не требуется. Предупреждай, если модели не существует.
6. magpie_list_models, magpie_status:
   - status показывает версию, маршруты и источник каждого из них, псевдонимы, сессии, количество вызовов / сбоев / среднюю задержку / токены для каждой модели за последние 7 дней, временно пропущенные модели, разрешённые папки и необработанные настройки.

## Надёжность и безопасность
- Классифицируй ошибки: шлюз недоступен, истёк тайм-аут, ошибка аутентификации, модель не найдена, превышен лимит запросов, ошибка сервера — с понятными сообщениями.
- Модели, у которых произошла ошибка аутентификации / модель не найдена / истёк тайм-аут / превышен лимит запросов / ошибка 5xx, перемещай в конец списка кандидатов на 10 минут.
- В режиме файла разрешено читать и записывать только внутри папок из списка разрешённых в настройках:
  - Перед сравнением разрешений получай реальный путь через realpath, чтобы блокировать выходы через .. и символические ссылки; в Windows сравнивай пути без учёта регистра.
  - Отклоняй двоичные файлы, ограничь размер отдельных файлов 5 MB, по умолчанию никогда не перезаписывай существующие файлы.
- Считай весь вывод сторонних моделей недоверенным материалом.
- Всё, что может записывать в папку ядра, может выполнять код через расширение — чётко укажи это в документации.

## Проблемы при упаковке mcpb
- Используй версию манифеста 0.3; user_config должен содержать: модели для каждой задачи, строку псевдонима, режим отображения, порог, папку данных, разрешённые папки (тип directory, multiple: true), URL шлюза, ключ (sensitive), тайм-аут.
- Многочисленные значения user_config раскрываются только в args, но не в env — передавай разрешённые папки через args.
- Claude Desktop не всегда подставляет ${DOCUMENTS}, ${DESKTOP}, ${DOWNLOADS}, ${HOME}; раскрывай их в сервере.
- Считай пустые настройки или значения, которые всё ещё читаются как "${...}", не заданными.
- Изменения в настройках расширения вступают в силу только после полного выхода из Claude через трей; поэтому повседневные изменения маршрутов выполняй через magpie_config.
- Установи @anthropic-ai/mcpb глобально с помощью npm, затем выполни mcpb validate и mcpb pack; добавь универсальную иконку размером 512×512 (без логотипов брендов).

## Тесты
Напиши tests/selftest.mjs и включи его в расширение. Используй фиктивный шлюз и временные папки, чтобы охватить:
- продолжение и изоляцию сессий, внедрение контекста, сохранение сессий после перезапуска;
- переключение на резервную модель и пропуск недавно завершивших работу с ошибкой моделей;
- recall;
- изменение конфигурации из чата;
- список разрешённых папок и блокировку выхода за его пределы;
- возобновление после сбоев обработки фрагментов и остановку, если выходной файл был отредактирован;
- сравнение нескольких моделей;
- статистику использования;
- горячую перезагрузку и автоматический переход на резервную модель при синтаксических ошибках.
Передавай .mcpb только после успешного прохождения всех тестов.
