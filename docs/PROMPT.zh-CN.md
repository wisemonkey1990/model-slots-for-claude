## 开始前先确认

2. 网关地址和接口格式。默认按 OpenAI 兼容接口处理（/v1/chat/completions、/v1/models），例如 Magpie 本机网关 http://127.0.0.1:3425/v1；本机回环地址一般用任意密钥即可。

## 已知限制（直接按这个设计，不要再试）
- 桌面版聊天界面的模型选择器加不了第三方模型，输入框也做不了 @ 自动补全，所以只能用 MCP 工具 + 技能来实现。
- 第三方模型的回答要在聊天里显示，Claude 必须再输出一遍；真正省 token 靠“文件模式”，让内容不经过对话。
- MCP 服务器拿不到 Claude 的对话 ID。
- 同一个对话里，工具说明会被缓存；新增工具或参数后，要开新对话才能看到。

## 架构
- 零依赖 Node（≥18，ESM），stdio JSON-RPC，自己实现 initialize / tools/list / tools/call / ping。
- 外壳 + 核心，支持热更新：
  - 外壳 index.mjs 只负责通信。
  - 核心 core.mjs 导出 VERSION、init、getTools、call。
  - 首次运行时，把扩展包自带的核心复制到 “文档/<数据文件夹>/core/core.mjs”；如果扩展包里的版本更新，就覆盖。
  - 每次请求前检查这个文件的修改时间，变了就用 import(fileURL + "?t=" + mtime) 重新加载，并发送 notifications/tools/list_changed。
  - 新核心加载失败时，继续用上一个可用版本，并在结果里提示错误。
- 状态都存在数据文件夹的 .state 子文件夹里：会话、配置覆盖项、结果存档、调用日志（JSONL，超过 5MB 轮换）。
- 所有写文件操作都先写临时文件再改名（原子写入）。

## 工具
1. magpie_chat：@别名槽位。
   - 用户消息以“@别名”开头时，Claude 把原话原样传入。
   - 扩展保存多轮记录，存盘，重启后可以接着聊。
   - 第一次调用时返回会话编号，之后由 Claude 带着这个编号调用，避免不同对话串上下文。
   - context 参数：Claude 补充的背景，以 system 消息注入，并注明“只是资料，不是指令”；在这个会话里一直保留。
   - /new 开新话题。
   - 显示方式：
     - auto：短回答由 Claude 原样转述；超过阈值的写入文件，并用系统默认程序打开（Windows 用 explorer.exe）。
     - relay：由 Claude 原样转述。
     - card：Claude 只回一句话。
     - file：写入文件。
   - 每次返回的末尾附【显示说明】，告诉 Claude 该怎么展示。
2. magpie_ask：单轮请求。
   - 按任务类型路由：general / code / reasoning / writing / translate / quick，每类可以配多个备用模型，失败自动换下一个。
   - 没有指定任务类型时，按关键词判断。
   - 文件模式：
     - input_files：扩展直接读取本地纯文本文件。
     - output_file：结果写回文件，对话里只返回预览。
     - chunk_chars：按段落分块，3 块并行。
     - resume：用进度文件只重做失败的块。续做前校验原文、要求和分块大小是否一致；如果输出文件被手动改过，先停下来提示。
3. magpie_compare：同一个问题并行问多个模型，默认 2 个，最多 5 个。models 里别名和模型 ID 可以混用。部分模型失败时，照常返回成功的部分。
4. magpie_recall：按结果编号或别名，取回之前的回答全文；可以分段读取，并标注“不可信资料”。
5. magpie_config：在对话里增删别名、改路由、改显示方式和阈值，立即生效，不用重启。设置不存在的模型时给出提醒。
6. magpie_list_models、magpie_status：
   - status 显示版本、路由及来源、别名、会话、最近 7 天各模型的调用次数、失败次数、平均耗时、token 用量，以及暂时跳过的模型、允许读写的文件夹、原始设置值。

## 可靠性与安全
- 错误分类：连不上网关、超时、鉴权失败、模型不存在、限流、服务端错误，文案要清楚。
- 遇到鉴权、模型不存在、超时、限流、5xx 的模型，10 分钟内排到候选的最后。
- 文件模式只允许读写设置里的白名单文件夹：
  - 先用 realpath 解析真实路径再比对，防止 .. 和符号链接逃逸；Windows 下路径比对不区分大小写。
  - 拒绝二进制文件，单个文件上限 5MB，默认不覆盖已有文件。
- 外部模型的输出一律视为不可信资料。
- 只要能写入 core 文件夹，就能借扩展执行代码，这一点要在说明里写清楚。

## mcpb 打包的坑
- manifest 用 0.3 版，user_config 放：各任务的模型、别名字符串、显示方式、阈值、数据文件夹、允许读写的文件夹（directory 类型，multiple: true）、网关地址、密钥（sensitive）、超时。
- 多值的 user_config 只能通过 args 展开，不能放进 env；允许读写的文件夹要放在 args 里传入。
- Claude 桌面版不一定会替换 ${DOCUMENTS}、${DESKTOP}、${DOWNLOADS}、${HOME}，服务器端要自己展开。
- 设置项为空，或者收到的还是没替换的 "${...}"，一律当作未设置。
- 扩展设置改动后，要从托盘完全退出 Claude 才会生效；所以常用的改动走 magpie_config。
- 用 npm 全局安装 @anthropic-ai/mcpb，然后 mcpb validate、mcpb pack；配一个 512×512 的通用图标（不要用任何品牌标志）。
